#### 내용 흐름 
컴퓨터안에 데이터는 모두 0과 1로 이뤄진 배열 덩어리들인데, 어떤 규칙을 적용하는가에 따라 의미가 달라짐. <br>
이러한 규칙들을 컨텍스트라 하며, 가령 CPU 가 이해할 수 있다면 *바이너리*, 아스키 코드로 사람의 언어로 표현된 것은 텍스트 파일이라 볼 수 있다.<br>
사람의 언어로 작성된 프로그램 실행시, 컴퓨터가 읽기 위해 기계어로 번역하는 과정이 반드시 필요하다. 이 과정을 컴파일이라 하는데, 컴파일 시스템이 CPU가 처리할수있게끔 기계어로 번역과 실행에 필요한 후처리 과정도 수행한다. <br>
즉 하나의 프로그램이 실행되기위해선 전처리, 컴파일, 어셈블리, 링크 과정을 거쳐간다. 각 단계마다 생성되는 산출물은 다음단계의 입력값으로 사용된다. <br>
재미있는점은 링크 단계인데, CPU가 읽을수있는 상태지만, 프로그램이 실질적으로 실행되진 않는다. 왜냐하면, 외부 함수의 위치를 정해주지 않았기 때문이다. 링크는 프로그램 헤더 내용을 통해 CPU에게 프로그램의 함수 관계를 선언함으로써 완전히 실행가능한 파일로 만든다. 

#### 어려웠던 것들 
- 인스트럭션 : CPU가 이해할수있는 명령어 집합
- 오버헤드 : 자원(e.g. 메모리)의 사용량
- 실행 가능 목적 프로그램 : CPU가 실행 가능한 파일 
- 재배치 가능 프로그램 :  외부 함수 위치를 모르는 파일
